# Интерфейс в стиле «Telegram на iPhone» — как перенести в другой проект

Этот файл описывает веб-интерфейс проекта **kindergarten-monitoring** так, чтобы его можно было
повторить в любом другом проекте: что взять из этого репозитория как есть, по каким правилам
строить новые экраны и что проверить перед тем, как считать экран готовым.

Документ написан и для человека, и для Claude: его можно целиком отдать Claude Code в новом
проекте вместе с путём к этому репозиторию (см. раздел 10).

---

## 1. Что именно мы повторяем

- **Внешний вид iOS / Telegram для iPhone**: большие заголовки, которые при прокрутке
  сворачиваются в полупрозрачную размытую панель; сгруппированные списки на сером фоне, как в
  «Настройках» iPhone; нижние шторки, которые смахиваются вниз; системные цвета Apple;
  шрифт SF Pro (на других системах — системный).
- **Плавные анимации на пружинах** (framer-motion): переходы между экранами, переключатели,
  сегменты, шторки, тосты — всё двигается физично, без линейных «появлений».
- **Разное поведение для телефона и компьютера** — это главное правило, а не украшение:

  | Что | Телефон (касание) | Компьютер (мышь, широкий экран) |
  |---|---|---|
  | Навигация | Нижний таб-бар | Боковая панель слева, клавиши 1–4 |
  | Окна | Нижняя шторка, смахивается вниз | Диалог по центру, закрывается Esc / фоном |
  | Подтверждения | Action sheet снизу | Компактный алерт по центру |
  | Действия в строке списка | Свайп влево | Кнопки появляются при наведении |
  | Обновление | Потянуть вниз (pull-to-refresh) | Кнопка «Обновить» в панели |
  | Скрыть уведомление | Смахнуть в сторону | Крестик |
  | Назад | Кнопка «‹ Назад» | Кнопка и Esc |

- **Светлая и тёмная тема** — автоматически по настройке системы.
- **Без эмодзи в «хроме»**: кнопки, заголовки, пункты меню — только текст и иконки lucide.
  Эмодзи допустимы там, где они по смыслу (реакции, текст пользователя).
- **Язык интерфейса** — живой русский, короткие фразы, без канцелярита и технических кодов
  ошибок; сервер сразу отдаёт понятные человеку сообщения.

Создать проект с нуля:

```bash
npm create vite@latest web -- --template react-ts
```

```bash
npm i framer-motion lucide-react
```

### 3.3. `styles.css` — какие разделы брать

Файл разбит на разделы комментариями `/* ---------- … ---------- */`. Брать:

- `:root` и `@media (prefers-color-scheme: dark)` — токены (см. раздел 4), сброс стилей, `body`;
- navigation bar with large title;
- tab bar;
- search, segmented, chips;
- grouped inset lists (Settings style) — секции, группы, ячейки, плашки;
- bottom sheet — шторки, action sheet, поля ввода, переключатель, степпер;
- buttons, misc — кнопки, пустые состояния, спиннер, скелетоны, тост, pull-to-refresh;
- login;
- desktop: sidebar layout, dialogs, hover — **обязательно**, без него компьютерная версия сломается.

**Не брать** (специфично для мониторинга): post card, failed reposts screen, external API
screen, storage usage. Их можно использовать как образцы, если нужен похожий экран.

После копирования: `npx tsc -b` должен пройти без ошибок, неиспользуемое удалить.

## 5. Анимации

```ts
// lib/motion.ts
export const spring      = { type: 'spring', stiffness: 420, damping: 38, mass: 0.9 } // элементы
export const softSpring  = { type: 'spring', stiffness: 260, damping: 30 }            // смена экранов
export const sheetSpring = { type: 'spring', stiffness: 380, damping: 40 }            // шторки и диалоги
```

Правила:

- **Переходы между экранами** (`App.tsx`, `variants`): вглубь (push) — новый экран въезжает
  справа на 60px, старый уходит влево на 40px; назад (pop) — наоборот; между вкладками —
  кроссфейд с лёгким масштабом 0.99. Уход экрана быстрый (0.12 с), появление — пружина.
- **Ползунки, которые «переезжают»** (активный сегмент, чипс, пункт боковой панели) — через
  `layoutId`, а не через вычисление координат.
- **Появление и исчезновение строк и плашек** — `AnimatePresence` + `height: 0 → 'auto'`, чтобы
  соседние элементы сдвигались плавно, а не прыгали.
- **Нажатие**: `whileTap={{ scale: 0.88–0.94 }}` на вкладках и чипсах; у ячеек — смена фона
  `:active`.
- **Жесты**: шторка закрывается, если её утянули вниз больше чем на 110px или быстро бросили
  (скорость > 600); строка открывает действия, если сдвинута больше половины ширины кнопок или
  брошена влево быстрее 400.
- **Не анимировать** то, что пользователь ждёт мгновенно: ввод текста, результаты поиска,
  переключение темы.
- Смена содержимого в одном месте (загрузка → данные, шаг 1 → шаг 2 в шторке) —
  `AnimatePresence mode="wait"` со сдвигом по x ±24px.

## 6. Компоненты: как собирать экран

### 6.1. Каркас экрана

```tsx
<Page
  title="Прокси"
  left={<button className="nav-button" onClick={onBack}><ChevronLeft size={26} /> Настройки</button>}
  right={<button className="nav-button" onClick={add}><Plus size={22} /></button>}
  accessory={<Segmented id="proxy-filter" options={…} value={filter} onChange={setFilter} />}
  onRefresh={reload}
>
  …секции…
</Page>
```

- Корневые вкладки — без `left`. Вложенный экран — слева «‹ Название родителя».
- `onRefresh` передавать везде, где данные могут устареть: Page сам решит — потянуть вниз
  на телефоне или кнопка с мышью.

### 6.2. Сгруппированный список («Настройки»)

```tsx
<div className="section">
  <div className="section-header">Хранение</div>
  <div className="group">
    <div className="cell">
      <div className="cell-icon" style={{ background: 'var(--orange)' }}><Clock size={17} /></div>
      <div className="cell-main">Хранить посты</div>
      <Stepper value={days} steps={[7, 14, 30, 60]} onChange={save} />
    </div>
    <button className="cell" onClick={open}>
      <div className="cell-icon" style={{ background: 'var(--indigo)' }}><Network size={18} /></div>
      <div className="cell-main">Прокси</div>
      <span className="cell-value">3</span>
      <ChevronRight size={18} color="var(--text-3)" />
    </button>
  </div>
  <div className="section-footer">Пояснение одной-двумя фразами: что будет, если поменять.</div>
</div>
```

- Ячейка ≥ 44px в высоту (минимальная цель касания Apple).
- Разделители между ячейками рисуются автоматически (`.cell + .cell::before`) и начинаются
  после иконки.
- Значение справа — `.cell-value` (серое), переход внутрь — шеврон `ChevronRight` цвета `--text-3`.
- Кнопка-действие внутри группы — `.cell.accent` (синий текст), опасное — `.cell.destructive`.
- **Каждое неочевидное действие объясняется в `section-footer`**, а не во всплывающих подсказках:
  на телефоне подсказок при наведении нет.

### 6.3. Окна и подтверждения

- Любая форма или многошаговый процесс — `Sheet`: слева «Отмена», справа жирное действие
  («Готово», «Добавить»), во время запроса вместо текста `Loader2` с классом `spinner`.
- Удаление и другие необратимые действия — только через `ActionSheet` с `destructive: true`
  и сообщением, что именно произойдёт.
- Результат действия — `toast('Прокси удалён')`; ошибка запроса — `toast(e.message)`
  (сервер уже прислал понятный текст).

### 6.4. Списки с действиями

`SwipeRow` с массивом `actions` (`label`, иконка lucide, цвет, `onClick`). Под списком на
телефоне — футер-подсказка «Смахните … влево, чтобы …», с мышью она не нужна.

### 6.5. Состояния

- Загрузка — скелетоны (`.skeleton`, `.skeleton-line`) в форме будущего контента, а не спиннер
  на весь экран.
- Пусто — `.empty` с иконкой, заголовком и одной фразой, что сделать.
- Ошибка, которую надо заметить, — `DismissibleNote` над содержимым.

## 7. Обязательные мелочи (без них «ломается» ощущение iOS)

1. **Поля ввода не меньше 16px** — иначе iOS Safari приближает страницу при фокусе.
   Моноширинные поля (`.field.mono`) тоже 16px.
2. `overscroll-behavior: none` на `body` и `overscroll-behavior-x: none` на `html` — иначе
   горизонтальный свайп в строке листает историю браузера, а pull-to-refresh дерётся с
   браузерным.
3. `overflow-x: clip` (не `hidden`) на `body` — иначе перестаёт работать `position: sticky`
   у навбара.
4. Во время открытой шторки — `document.body.style.overflow = 'hidden'` (уже есть в `Sheet`).
5. Действия под свайпом показываются, только когда строка реально сдвинулась
   (`opacity` от `x`) — иначе они просвечивают при касании.
6. Прокрутка каждого экрана запоминается и восстанавливается при возврате назад
   (уже в `Shell`).
7. Повторное нажатие на активную вкладку — плавная прокрутка наверх.
8. Ховер-эффекты — только внутри `@media (hover: hover) and (pointer: fine)`, чтобы на
   телефоне не «залипали» после касания.
9. Копирование в буфер — только через `copyText()`: на HTTP `navigator.clipboard` недоступен.
10. `-webkit-tap-highlight-color: transparent` на всём — без серых вспышек при касании.
11. PWA: `manifest.json`, `apple-touch-icon`, `theme-color` для светлой и тёмной темы — сайт
    можно добавить на экран «Домой» и он откроется без адресной строки.

## 8. Тексты

- Кнопки — глагол или существительное без точки: «Добавить», «Готово», «Сменить прокси».
- Футеры секций — полные предложения с точкой, объясняют последствия настройки.
- Числа — с правильными окончаниями через `plural(n, 'пост', 'поста', 'постов')`, дробные — с
  запятой (`1,4 МБ`, `2,7%`).
- Время — «только что», «5 мин назад», «вчера», «7 окт.» (`relative()`, `shortDate()`).
- Ошибки — что случилось и что сделать: «Прокси включены, но список пуст — добавьте прокси
  или выключите их», а не «Error 409».
- Эмодзи — только там, где они часть содержимого.

## 9. Чек-лист готового экрана

Каждый новый экран проверяется в двух размерах, в светлой и тёмной теме:

- [ ] **Телефон 375×812**: нет горизонтальной прокрутки; цели касания ≥ 44px; свайпы и
      pull-to-refresh работают; шторка смахивается вниз; текст не обрезан; при фокусе в
      поле страница не приближается.
- [ ] **Компьютер ≥ 1000px**: боковая панель вместо таб-бара; диалоги по центру и закрываются
      Esc; действия строк видны при наведении; есть кнопка «Обновить»; Esc возвращает назад.
- [ ] Тёмная тема: нет белых пятен и нечитаемого текста (особенно в шторках).
- [ ] Загрузка, пустое состояние и ошибка выглядят осмысленно.
- [ ] Каждое неочевидное действие объяснено в футере секции.
- [ ] `npx tsc -b` и `npm run build` проходят.

## 10. Как запустить это в новом проекте через Claude Code

1. Откройте новый проект в Claude Code (вкладка Code в приложении Claude).
2. Положите этот файл в новый проект, например в `docs/ui-guide.md`.
3. Напишите Claude примерно так:

   > Сделай веб-интерфейс этого проекта по `docs/ui-guide.md`. Исходники UI-кита лежат в
   > `C:\path\to\Desktop\kindergarten-monitoring\frontend\src` — скопируй оттуда файлы из
   > раздела 3.1, адаптируй файлы из 3.2 и нужные разделы `styles.css` из 3.3. Разделы
   > приложения: … (перечислите вкладки и что на каждой). Проверь каждый экран по чек-листу из
   > раздела 9 на телефоне и на компьютере.

4. Чтобы правило «всегда проверять телефон и компьютер, без эмодзи в кнопках» действовало во
   всех будущих разговорах в новом проекте, попросите Claude добавить в `CLAUDE.md` нового
   проекта строку: «Интерфейс строится по `docs/ui-guide.md`».

Если новый проект не на React (Vue, Svelte, обычный HTML), из этого репозитория всё равно
берутся `styles.css` и раздел 4–9 как спецификация, а компоненты переписываются на нужный
фреймворк с теми же классами и теми же значениями пружин.
