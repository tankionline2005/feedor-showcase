# Kindergarten Monitoring

Мониторинг Telegram-каналов: пул пользовательских аккаунтов собирает посты из списка каналов, пересылает их в один канал-агрегатор и показывает в веб-интерфейсе в стиле Telegram на iPhone — лента, топы за период, сортировка по просмотрам, ER, реакциям, комментариям и репостам.

## Как устроено

```
backend/app/
  worker/      фоновый процесс: аккаунты, вступление в каналы, приём и опрос постов,
               обновление метрик, репост, очистка старых постов
  web/         FastAPI: вход, посты, каналы, аккаунты, настройки
  tg/          разбор ссылок и сообщений Telegram, создание клиентов
frontend/      React + Vite + Framer Motion (iOS-интерфейс)
```

- **web** и **worker** — два процесса одного образа, общаются только через базу.
- Все запросы аккаунта к Telegram идут по одному с паузой 1–1,6 с. FloodWait ставит аккаунт на паузу, мёртвая сессия снимает с него каналы — их подхватят другие аккаунты.
- При вступлении в новый канал подтягиваются его посты за последние 7 дней (`backfill_days`, не больше 1000; история не пересылается в группу, её превью качаются в отдельной очереди с низким приоритетом).
- Новые посты приходят из потока обновлений; дополнительно каждый канал опрашивается раз в 5 минут (`poll_interval_sec`), потому что Telegram доставляет обновления каналов не всегда.
- Метрики обновляются тем чаще, чем свежее пост: первые 2 минуты — каждые 10 с, дальше реже, до часа — каждые 2 минуты, потом 5 мин / 15 мин / 1 ч (`REFRESH_TIERS` в `worker/collector.py`).
- ER = (реакции + комментарии + репосты) / просмотры × 100%.
- Прокси — общий пул (Настройки → Прокси), SOCKS5 и MTProto (кроме fake-TLS). Список вставляется целиком, каждый прокси сразу проверяется. Аккаунты получают прокси автоматически (не больше `accounts_per_proxy`, по умолчанию 5) и держатся за свой; вход нового аккаунта тоже идёт через прокси. Воркер проверяет прокси раз в 5 минут: после двух неудач подряд прокси считается мёртвым, его аккаунты переезжают на другие, а если свободных рабочих нет — ждут. Напрямую с IP сервера аккаунты не подключаются никогда.
- Аккаунты добавляются по номеру, строкой сессии или пачкой файлов: `.session` (Telethon/Pyrogram) с `.json` от продавца (api_id и устройство берутся оттуда), `.zip`, `.txt` со строками сессий. tdata пока не поддерживается.
- Метрики: ER = (реакции + комментарии + репосты) / просмотры; FR = репосты / просмотры; FR+ = FR поста / средний FR канала (`app/fr_plus.py`).
- Уведомления — свой бот из @BotFather (Настройки → Уведомления): отключённые аккаунты, долгие ограничения, нехватка прокси, нерабочие прокси, сломанный репост, недоступные каналы; сводка раз в сутки и `/status` в чате с ботом.
- Внешний API только для чтения: `/api/v1` (`project`, `posts`, `posts/new`, `posts/{id}`, `posts/{id}/preview`, `channels`, `channels/{id}`, `stats`), ключ в заголовке `X-API-Key`, 120 запросов в минуту, CORS разрешён. Ключ проекта отдаёт `my_channel` — канал проекта, ради развития которого собираются данные (`/posts?channel=my`, флаг `is_my_channel` у постов и каналов). Ключ, сброс и документация — Настройки → API (`backend/app/web/public_api.py`, описание — `frontend/src/lib/apiDocs.ts`).
- Вход: пользователи — кнопкой «Войти через Telegram» (сайт выдаёт одноразовый код, бот уведомлений присылает кнопку «Подтвердить вход», `app/logins.py`); у пользователя один или несколько проектов (`app/projects.py`), у каждого свой тариф (`app/plans.py`), каналы, ключ API, канал проекта и сотрудники. Сотрудники проекта («Совместный мониторинг», `app/members.py`) входят логином и паролем, который выдаёт владелец; когда тариф проекта заканчивается, они удаляются. Админ входит логином и паролем из `.env` по адресу `/#/admin` — обычная страница входа этой формы не показывает. Управление (аккаунты, прокси, настройки, пользователи) доступно только админу.
- Закрытые каналы (по ссылке-приглашению) держат запасной аккаунт (всегда 2 аккаунта в канале, `PRIVATE_ACCOUNTS`): он вступает через 1–6 часов после основного через другой прокси, раз в 6 часов проверяет, что он ещё в канале, и сразу перехватывает сбор, если основной потерял доступ (`worker/reserves.py`).
- «Мои группы» (`web/groups.py`): пользователь добавляет бота в свою группу и подключает её — публичную по ссылке, закрытую из списка групп, куда он сам добавил бота (бот узнаёт их из обновлений `my_chat_member`, ссылку-приглашение бот разрешить не может). Добавить можно только группу, где пользователь состоит; лимит — в тарифе (Beta Tester — 3). Кнопка отправки поста тогда предлагает: личные сообщения или одна из групп.
- Каналы общие: каждый канал в системе один, проекты на него подписываются (`project_channels`), и один аккаунт обслуживает всех. Пользователь видит в ленте, топе, каналах, автообновлении и API только каналы текущего проекта, без внутренностей (аккаунтов, банов, группы-агрегатора; `app/scope.py`), и может держать их не больше, чем позволяет тариф проекта (свой канал проекта не считается). Админ видит все каналы и сколько пользователей у каждого; добавленные им каналы «удерживаются». Канал, который никто не отслеживает и не держит админ, покидается через сутки (закрытый — через 30 дней), если его не добавят снова (`app/orphans.py`).
- Сайт ставится на экран «Домой» как приложение (PWA, `frontend/public/manifest.json`).
- Репост распределяется по аккаунтам: пост из публичного канала пересылает наименее загруженный за час аккаунт (не больше `REPOSTS_PER_ACCOUNT_HOUR` = 100 в час), из приватного — только участник.
- Каналы, запрещённые в стране аккаунта (Telegram отдаёт заглушку «This channel can't be displayed…»): аккаунт выходит из канала и попадает в его `restricted_for`, заглушки удаляются, канал переходит другому аккаунту. Если подходящих нет — статус `restricted`, канал подключится сам, когда появится новый аккаунт.
- Репост в публичную группу-агрегатор: пересылка (альбом — одним сообщением). Аккаунты сами вступают в группу по @username или ссылке-приглашению, админы не нужны; в группе должны быть разрешены сообщения и медиа от участников. Медленный режим группы и спам-ограничение аккаунта (PeerFlood) ставят репост через этот аккаунт на паузу, пост ждёт в очереди. Если в исходном канале запрещена пересылка, уходит текст со ссылкой на оригинал.

## Деплой на текущий сервер

```bash
scripts/deploy.sh
```

Скрипт отправляет на сервер закоммиченный `HEAD` (через `git archive` по SSH-ключу `~/.ssh/kindergarten_vps`) и пересобирает контейнеры. Секреты лежат в `/opt/kindergarten-monitoring/.env` на сервере, код — в `/opt/kindergarten-monitoring/src`.

## Запуск на новом сервере

Нужны Docker и Docker Compose.

```bash
git clone https://github.com/tankionline2005/kindergarten-monitoring.git
cd kindergarten-monitoring
cp .env.example .env    # заполнить пароли, SECRET_KEY, TG_API_ID/TG_API_HASH
docker compose up -d --build
```

Интерфейс откроется на `http://<сервер>/`, вход админа — `http://<сервер>/#/admin`. Дальше:

1. **Настройки → Добавить аккаунт**: номер телефона → код из Telegram → облачный пароль, если включён. Либо вставить готовую строку сессии Telethon.
2. **Настройки → Репост → Группа**: `@username` или ссылка-приглашение публичной группы-агрегатора.
3. **Каналы → +**: ссылки на каналы, по одной в строке.

Логи: `docker compose logs -f worker`.

HTTPS на своём домене: A-записи домена (`@` и `www`) указывают на сервер, в `.env` — `DOMAIN`, `COMPOSE_PROFILES=https`, `WEB_PORT=127.0.0.1:8000`, `COOKIE_SECURE=true`, `FORWARDED_ALLOW_IPS=*`. Тогда поднимается Caddy (`deploy/Caddyfile`): сам получает и продлевает сертификат, переводит `www` и голый IP на домен. Прежние адреса сайта можно перечислить через пробел в `OLD_DOMAINS` (например, `OLD_DOMAINS=old.com www.old.com`, их A-записи тоже на сервер) — они переводят на `DOMAIN` с тем же путём. По `DOMAIN` же строятся ссылки на сайт в сообщениях бота.

## Локальная разработка

```bash
cd backend
python -m venv .venv && .venv/Scripts/pip install -r requirements-dev.txt   # Windows
python -m app.devseed            # демо-данные в backend/data/dev.db (SQLite)
python -m uvicorn app.web.main:app --port 8000
python -m app.worker             # нужен реальный аккаунт и TG_API_ID/TG_API_HASH в .env
python -m pytest
```

```bash
cd frontend
npm install
npm run dev                      # http://localhost:5173, /api проксируется на :8000
```

Без `.env` вход админа: `http://localhost:5173/#/admin`, `admin` / `admin`.
